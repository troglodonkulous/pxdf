# Test patterns

Source material for Part A of `docs/CAPTURE_PLAN.md` — patterns displayed in
Ledset while capturing its UDP output.

## Ledset will only load uncompressed AVI

Two independent constraints, both read out of the vendor's code and then
confirmed against the real DLL:

**1. Only video extensions are listed.**
`MediaListProcessor.CheckIfVideoFile` (`decompiled/LedSet.decompiled.cs:3578`)
compares the file extension against exactly:

```
.MP4  .AVI  .FLV  .MOV  .WMV  .MPG
```

There is no image-loading code anywhere in LedSet.exe. A `.png`, `.bmp` or
`.gif` in the media folder is skipped during the folder scan and simply never
appears in the list — with no error and nothing in the UI to say why.

**2. Only codecs DirectShow can resolve will decode.**
`MediaListInitThreadHandler` (`:3035`) hands each listed file to
`VideoGrabber.dll`, a thin DirectShow wrapper that bundles no codecs of its
own. An H.264-in-AVI file passes the extension filter, appears in the list, and
then produces neither a thumbnail nor playback.

> **`01`–`08` are 64 × 40 and are retired.** They were authored for the 8 × 5
> rig; `mapper play` rejects them on the 10 × 5 shop floor and on the 10 × 12
> deep rig. Only `09-gradient24-8x8_4P-10x5.avi` and `10-sweep-8x8_4P-10x5.avi`
> are 80 × 40. The 10 fps below is likewise the Ledset-era rate —
> `DEFAULT_FPS` is 30, see `docs/RUNSHEET-10x5-4P.md` §11.

So the patterns here are **uncompressed 24-bit BI_RGB AVI, 64x40, 10 fps** —
the same container as `07-tilewalk.avi`, which is the file confirmed working on
this rig.

`07-tilewalk.avi` is the original ground-truth file and the one
`tilewalk_timing.md` describes. It is deliberately **not** regenerated by the
script below unless you pass `-IncludeTilewalk`.

The `.png` files are the design reference for each pattern. The `.bmp` and
`.gif` files are left over from earlier attempts to get Ledset to see a still
image; nothing reads them and they can be deleted.

`thn/` is Ledset's thumbnail cache. Ledset only populates it when the folder is
absent, so after changing any pattern either delete `thn/` or press **Refresh**
in Ledset — otherwise the new files show "Thumbnail Lost".

## Regenerating

**`01`–`08` cannot be regenerated, deliberately.** Their two generators —
`tools/New-PatternAvi.ps1` and `tools/make_test_patterns.py` — were deleted on
2026-08-13. They only ever emitted the retired 64 × 40 set, which `play`
rejects on both the shop and the deep rig, and two independent implementations
of one dead asset set is twice the maintenance for none of the value. The
`.avi` files themselves stay: `06-halves` and `07-tilewalk` are the source
material for captures this project still cites as evidence, and
`mapper/tests/test_oracle_capture.py` grades against `07-tilewalk.avi`.

The live generator is `gradient24` at any geometry:

```powershell
.\tools\oracle\make-gradient-avi.ps1 -Cols 10 -Rows 5 -TileSize 8 -Seconds 6 `
    -OutFile .\test-patterns\09-gradient24-8x8_4P-10x5.avi
```

Note the writer requires `Width * 3` to be a multiple of 4 (DIB row alignment);
it throws rather than emitting a subtly corrupt file.
